# media-server

Self-hosted [Jellyfin](https://jellyfin.org/) media server, deployed with Docker
Compose and NVIDIA hardware transcoding. Designed to be portable: the whole
deployment is captured here so it can be redeployed on a different host (e.g. a
dedicated mini PC) by cloning this repo and re-running the bootstrap.

## What's tracked vs. not

| Tracked in git | Not tracked (gitignored) |
| --- | --- |
| `docker-compose.yml` — the deployment | `.env` — real values for a host |
| `.env.example` — parameter template | `config/` — Jellyfin runtime state |
| `bootstrap.sh` — host setup | `media/` — your library |
| `docs/host-setup.md` — the runbook | |

`config/` is **generated by the container on first run** (user database, device
tokens, cached artwork) — it's per-instance state, never committed. To move an
existing server to a new host, copy that `config/` directory across.

## Prerequisites (host setup)

Docker Engine + Compose plugin and the NVIDIA Container Toolkit. On a fresh
Debian 13 box, run the bootstrap once (needs sudo):

```bash
sudo ./bootstrap.sh
```

Then start a new shell so docker-group membership takes effect. See
[`docs/host-setup.md`](docs/host-setup.md) for the step-by-step manual version
and what each command does.

Verify GPU passthrough works before continuing:

```bash
docker run --rm --gpus all nvidia/cuda:12.6.0-base-ubuntu24.04 nvidia-smi
```

You should see your GPU listed *from inside the container*.

## Run it

```bash
cp .env.example .env      # then edit .env for this host (PUID/PGID/TZ/paths)
mkdir -p config media     # data dirs (gitignored), owned by your user
docker compose up -d
```

Open the web UI at `http://<host>:8096` (or your `HTTP_PORT`) and complete the
setup wizard. Point libraries at the paths under `/media` inside the container.

### Enabling hardware transcoding

The GPU is exposed to the container, but Jellyfin still needs it switched on:
**Dashboard → Playback → Transcoding → Hardware acceleration → NVIDIA NVENC**,
then enable the codecs your GPU supports and save.

## Configuration

All knobs live in `.env` (see `.env.example` for the documented template):

| Var | Meaning |
| --- | --- |
| `PUID` / `PGID` | user/group that owns config + media (`id` to find yours) |
| `TZ` | IANA timezone, e.g. `America/Chicago` |
| `JELLYFIN_IMAGE` | image + tag (pin a version for reproducibility) |
| `HTTP_PORT` | host port for the web UI |
| `CONFIG_DIR` / `MEDIA_DIR` | where config + media live on the host |

## Common commands

```bash
docker compose up -d        # start / apply changes
docker compose logs -f      # follow logs
docker compose pull         # fetch a newer image
docker compose down         # stop and remove the container (keeps config/)
```

## Migrating to another host

1. Install prerequisites there: `sudo ./bootstrap.sh`.
2. Copy this repo + your `.env` + the `config/` directory to the new host.
3. Repoint `MEDIA_DIR` at the new machine's storage.
4. `docker compose up -d`.
